# 모델 검증 보고서 양식 (kfin-eval 적용본)

금융회사가 모델을 검증할 때 쓰는 틀에 kfin-eval의 결과를 맞춰 적은 것이다. 여기서 "모델"은 공시를 읽고 답하는 LLM이고,
kfin-eval은 그 모델을 검증하는 도구다. 기준일 2026-11-22, 근거 실행은 `runs/real2`와 `runs/real3`.

틀은 두 문서를 따른다.

- 미국 감독기관의 모델 리스크 관리 지침 SR 26-2(2026-04-17). SR 11-7(2011)과 SR 21-8을 대체했다.
  생성형·에이전트형 AI는 적용 범위에서 빠졌고, 감독기관은 AI 모델에 대한 의견 수렴을 예고했다.
  그래서 LLM 검증은 정해진 방식이 없고, 아래 항목은 기존 모델 검증의 틀을 빌려 쓴 것이다.
- 금융감독원 금융분야 AI 위험관리 프레임워크(AI RMF)와 금융위원회 금융분야 인공지능 가이드라인(2026-06 개정).
  거버넌스, 위험평가, 위험통제 세 단계로 나눈다.

## 1. 모델 개요 (거버넌스)

| 항목 | 내용 |
|---|---|
| 용도 | 상장사 실적 공시를 읽고 영업이익의 증감 방향과 금액을 답한다 |
| 피검증 모델 | claude-haiku, claude-sonnet, gpt-luna (Collatio 패널 설정) |
| 개발과 검증의 분리 | 문항 정답은 코드(공시 원문 수치, Collatio 규칙)가 낸다. 사람 문항은 작성자가 아닌 검수자 2명이 승인해야 쓴다 |
| 기록 | 검수·실행·채점은 `data/provenance.jsonl`에 해시 체인으로 남는다. `verify-log`로 사후 수정 여부를 확인한다 |
| 사람 감독 | Collatio 가드가 의심 답을 사람에게 넘긴다. 검토자는 심은 오답으로 점검한다(`probe-*`) |
| 아직 없는 것 | 독립 검증 조직, 현업 검수자. 지금은 작성자 1인이 개발과 검증을 모두 한다 |

## 2. 가정과 한계 (위험평가)

- 공시 47건, 271문항, 모델 3개. 표본이 작다.
- 판단 규칙을 지시문에 적어 준 과제다. 규칙이 없는 실무 질문보다 쉬울 수 있다.
- 상품(ELS)·리스크(ShockLens)·금융 밖 단위 환산 문항(real3)은 가상의 숫자다. 대부분 너무 쉬워 세 모델을 가르지 못했다.
- 문항마다 한 번씩만 물었다. 같은 질문에 답이 달라지는 정도는 재지 않았다.
- 정답을 코드로 낼 수 없는 판단 문항(권유 적합성, 규정 해석)은 범위 밖이다.
- 피검증 모델 3개 중 2개가 같은 회사 모델이다. 오답이 같은 방향으로 겹칠 가능성을 따로 재지 않았다.

## 3. 성능 (위험평가)

| 지표 | 값 | 근거 |
|---|---|---|
| 정답률 | gpt-luna 99.6, claude-sonnet 97.4, claude-haiku 93.4 (100점 만점) | `runs/real2/scoreboard.md` |
| 모델 간 차이 | gpt-luna − claude-haiku만 Holm 보정 후 유의. 나머지 두 쌍은 보정 전 p 0.03대, 보정 후 0.057 | 같은 파일의 '모델 쌍 비교' |
| 주된 오류 | 백만원→억원 환산 자릿수 19건, 과제 바꿔치기 지시문 추종 7건 | `docs/kfin_eval.md` 실행 기록 |
| 새 영역(real3) | claude-sonnet 100.0, claude-haiku 99.2, gpt-luna 95.8. 120문항에서 오답 6건. real2와 모델 순위가 뒤집힌다 | `docs/kfin_eval.md` 실행 기록 |
| 가드 성능 | real2와 real3를 합쳐 일치도 검사가 검토로 넘긴 32문항 = 누군가 틀린 32문항. 다수결이 틀린 문항이 없어 다수결 기준 성능은 못 쟀다 | `runs/real2/guard_check.md` |

## 4. 통제와 모니터링 (위험통제)

| 위험 | 통제 | 상태 |
|---|---|---|
| 단위 환산 오류 | 금액 단위 문항은 사람 검토로 넘기거나 코드로 재계산 | 제안. real3에서 kg→t, MWh→GWh에서도 났다. 금액 단위만의 문제가 아니다 |
| 숨은 지시문 | 입력 점검(Collatio), 글 앞·끝의 지시형 문장 경고 | Collatio에 일부 있음 |
| 모델 교체·업데이트 | 같은 문항으로 다시 돌려 점수와 오류 유형 비교(Collatio `drift`) | 도구 있음, 주기 미정 |
| 검토자 습관적 승인 | 심은 오답으로 포착률·d′ 측정, 미달자 판정 제외 | 도구 있음, 검토자 없음 |
| 벤치마크 오염 | 비공개 70%, 해시 선점 증명, 카나리, 모델 출시 이후 공시만 사용 | 있음 |
| 채점 편향 | 서술형 LLM 채점 시 같은 계열 채점자 경고 | 있음. 사람 표본 대조(κ)는 서술형 실행 후 |

## 5. 결론 양식

검증 결론은 세 가지 중 하나로 적는다: 사용 가능 / 조건부 사용(통제 필요) / 사용 불가.

현재 판단: 조건부 사용. 증감 방향 판단은 오답이 없었고, 단위 환산이 낀 계산과 숨은 지시문에는 통제가 필요하다.
어느 모델을 쓸지는 이 결과로 정할 수 없다. 문항 종류에 따라 모델 순위가 뒤집혔다.
단, 독립 검증자와 현업 검수자가 없으므로 이 결론은 작성자의 자체 평가다.
