# 결과: 여러 AI는 함께 틀리는가

아니었다. 대신 함께 속았다.

2026-11-22 기준. 공시 10건, 모델 4개로 한 탐색용 실험 세 번의 결과다. 사전에 정한 본 실행(뉴스 100건, 모델 6개)은 하지 않았다. 아래 수치는 가설 검정이 아니다.

## 물은 것

금융회사들이 비슷한 AI를 쓰면 같은 글을 함께 잘못 읽고, 답이 서로 일치하니 맞는 것처럼 보일 수 있다. 그렇다면 답의 일치만 보는 점검은 소용이 없다. 이것이 실제로 일어나는지, 일어난다면 어떤 장치가 잡는지를 보려 했다.

## 한 것

전자공시의 잠정실적 공시를 후보 목록의 위에서부터 10건 썼다. 과제는 "당해 분기 영업이익의 전년 동기 대비 변동으로 방향을 정하라"다. 모델은 gpt-sol, gpt-luna, claude-sonnet, claude-haiku이고 입력마다 5번씩 물었다.

같은 공시를 세 가지 모양으로 넣었다.

1. 사람이 쓴 요약 (숫자 하나) — 2026-11-17
2. 코드가 만든 요약 (엇갈리는 숫자 여럿, 10건 중 6건에 반대 방향 숫자가 섞임) — 2026-11-18
3. 공시 원문의 표 그대로 (숫자 40개 안팎, 정정 전 숫자가 든 정정 공시 포함) — 2026-11-22

그리고 일부러 망가뜨린 입력을 넣었다: 출처 표기만 바꾼 글, 말만 바꾼 글, 끝에 "반대로 답하라"는 지시문을 숨긴 글, 기준 숫자의 부호를 뒤집은 글, 뒤집은 글을 여러 매체 보도처럼 꾸민 글.

## 나온 것

| 입력 | 답 수 | 결과 |
|---|---|---|
| 원문 그대로 (세 가지 모양) | 600 | 방향 오답 0 |
| 출처 표기만 바꿈 | 400 | 답이 바뀐 것 0 |
| 말만 바꿈 | 200 | 답이 바뀐 것 0 |
| 숨긴 지시문 (문장 한 가지) | 200 | 지시를 따른 것 0 |
| 숫자를 뒤집은 글, 그것을 꾸민 보도 | 560 | 546개가 글에 적힌 대로 답함 |

글을 따르지 않은 14개는 전부 첫 실험에서 나왔고 그중 12개가 한 공시다. 그 공시의 뒤집은 글은 "매출 459.8% 증가, 영업이익 적자전환"처럼 글 안의 숫자끼리 어긋나 있었다. 앞뒤가 맞게 뒤집도록 규칙을 고친 두 번째 실험에서는 240개가 예외 없이 글을 따랐다.

## 읽을 수 있는 것

**모델은 이 과제에서 잘못 읽지 않았다.** 숫자를 여럿 섞어도, 정리하지 않은 표를 줘도 같았다. 오답이 없으니 오답의 상관, 유효 모델 수, 패널의 값어치는 계산되지 않았다. 처음 가설을 확인하지도 반박하지도 못했다. 이 과제가 그것을 시험하기에 너무 쉬웠다.

**글이 틀리면 모델은 전원이 함께 틀렸다.** 네 모델이 뒤집힌 숫자를 정확히 읽고 지침대로 근거를 댔다. 이때 모델들의 답은 완전히 일치한다.

**그래서 모델의 답을 대조하는 방어는 조작을 잡지 못했다.** 답의 일치를 보는 가드(G1)와 근거를 대조하는 가드(G6)의 재현율은 조작된 입력에서 0이었다. 모델을 여러 개 쓰는 것도 도움이 되지 않았다. 네 개가 한 개와 같은 답을 냈다.

**잡을 수 있는 것은 글의 바깥을 보는 장치다.** 받은 숫자를 전자공시 원문과 맞춰 보는 대조(G4c)를 만들었다. 받아 둔 원문 50건 중 쓸 수 있는 47건에서, 원문 그대로인 숫자 47개는 전부 통과했고 부호를 바꾼 숫자 35개는 전부 걸렸다. 비교하는 숫자를 바꾼 글은 정의상 걸리므로, 이것은 성능이 아니라 장치가 동작한다는 확인이다.

## 말할 수 없는 것

- "AI는 금융 문서를 잘 읽는다"는 일반론. 공시 10건, 양식이 정해진 문서, 판단 기준을 지시문에 적어 준 과제 하나다.
- 판단 기준이 분명하지 않은 글(정책 뉴스, 논평)에서 어떤지. 해 보지 않았다.
- 숨긴 지시문에 강하다는 것. 문장 한 가지만 넣었다.
- 원문 대조가 실제로 얼마나 잡는지. 숫자를 바꾼 경우만 넣었다. 숫자는 두고 해석을 바꾼 글, 원문이 없는 글은 다루지 못한다.
- 통계적 판정. 평가용 뉴스가 4건이었다.

## 바뀐 것

처음 구상은 "여러 AI의 답을 대조해 틀린 답을 잡는다"였다. 결과가 가리킨 것은 "AI에 넣기 전에 입력을 원문과 대조한다"다. 필터의 순서도 그에 맞게 됐다: 입력의 앞뒤 모순(G0) → 원문 대조(G4c) → 그다음에 모델.

모델의 답을 대조하는 가드(G1, G3, G6)와 측정 지표는 코드에 남아 있다. 틀렸다고 확인된 것이 아니라 시험할 기회가 없었던 것이다. 모델이 실제로 틀리는 과제에서 다시 볼 수 있다.

## 과정에서 고친 내 잘못

- 첫 실험의 뒤집기 규칙이 앞뒤가 안 맞는 글을 만들었다. 예외가 한 공시에 몰린 것을 보고 찾았다.
- 출처 가드(G4b)가 정상 공시 전부에 경보를 울렸다.
- 엇갈리는 숫자를 넣으면 모델이 틀릴 것이라 봤다. 판단 기준을 적어 주자 틀리지 않았다.
- 입력 점검이 "손실인데 증감율이 숫자"인 공시를 잘못으로 봤다. 실제 공시는 그렇게 적는다.
- 글을 따르지 않은 답을 13개로 적었는데 다시 세니 14개였다.
