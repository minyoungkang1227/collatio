# 필터로 쓰기

EchoGuard의 본체는 가드다. AI의 답이 사람이나 다음 시스템으로 넘어가기 전에 걸러서, 의심스러운 것을 사람에게 넘긴다. 답을 고치지는 않는다.

`pipeline`은 그 가드가 얼마나 잘 잡는지 재는 실험이고, `filter`는 가드를 실제로 쓰는 창구다. 둘은 `guard.py`의 같은 함수를 부른다.

## 한 건 판정하기

```python
from echoguard.filter import screen

verdict = screen(
    outputs,                  # 모델 이름 → 그 모델의 반복 답들
    figure=-32.0,             # 글에 적힌 기준 지표의 값 (알 때만)
    primary_verified=True,    # 공시·정부 발표 원문을 실제로 확인했는가
    n_independent=1,          # 따로 확인해 준 독립 출처 수
)
verdict.decision   # "통과" 또는 "검토"
verdict.reasons    # 걸린 이유들
```

공시 숫자 한 건을 실제 모델에 묻고 판정하려면 `python -m echoguard.filter --numbers 공시.json`. API 키와 비용이 든다.

## 무엇을 보는가

| 검사 | 걸리는 경우 | 필요한 정보 |
|---|---|---|
| 응답 | 답을 내지 못한 모델이 있다 | 없음 |
| G1 답의 일치 | 모델들의 방향이 갈린다 | 없음 |
| G4b 출처 대조 | 1차 출처가 확인되지 않았고 독립 출처가 기준보다 적다 | 출처 확인 결과 |
| G6 근거 대조 | 근거가 지침과 어긋난 모델이 있다 | 글의 기준 지표 값 |

하나라도 걸리면 검토다.

## 알아둘 것

- 필요한 정보를 주지 않은 검사는 하지 않는다. 판정의 `checks`에 `ran=False`로 남는다. 검사를 하지 않은 것은 통과가 아니다. 출처 정보 없이 받은 "통과"는 답이 일치했다는 뜻일 뿐이다.
- 출처 확인은 이 필터가 하지 않는다. 호출하는 쪽이 확인한 결과를 넘긴다. 글에 붙은 출처 표기를 그대로 넘기면 G2와 같아져서 조작에 뚫린다.
- G3(말 바꿔 다시 묻기)와 G5(학습 가드)는 아직 필터에 넣지 않았다. G3는 말 바꾼 글을 만드는 부분이 없고, G5는 학습할 실제 응답이 없다.
- 기준값(일치 0.8, 출처 2곳)은 임시다. 가드의 실제 성능은 아직 재지 못했다. 이 필터의 "통과"를 근거로 실제 판단을 내려서는 안 된다.
